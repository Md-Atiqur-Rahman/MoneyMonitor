From a card purchase to a paid bill

A card purchase moves no money on the day. Each month's purchases become a statement on the 1st, joined by that month's card EMIs, and are paid by the 15th.

The month's Due, and what is saved

Due means what is still to pay this month, the same number on Home, Dues and Reports. A negative result is called Short, never savings.

flowchart TB
  BI["Budget item
estimate − spent"] --> Q{"paid in full?"}
  Q -->|"yes"| OK["✓ Fully paid"]
  Q -->|"struck through
won't pay"| SK["Not paying this month
leaves the budget and Due"]
  Q -->|"no"| EX["Expenses still to pay"]
  NL["Loans not on a card"] --> LI["Liabilities still to pay"]
  PD["Borrowing whose pay month has come"] --> LI
  EX --> DUE(["Due this month"])
  LI --> DUE
  DUE --> RES{"Money in − Loan & Card Paid
− Cash expenses − Due"}
  RES -->|"≥ 0"| SAVE["Saved so far (after dues)"]
  RES -->|"< 0"| SHORT["Short so far (after dues)"]
Budget: Save / Short = Income (earned + borrowed) − Payments due this month − Spending plan Reports: Saved / Short = Money in − Loan & Credit Card Paid − Cash expenses − Due this month Dues: Left after paying the due = Bank balance − Due this month

Loans

A card loan can run in installments from the start, or be one amount that is later converted into EMI. Either way its month can be moved, and Pay appears once that month has come.

stateDiagram-v2
  direction LR
  [*] --> Pending: New loan, money received counts as income
  Pending --> Due: its month has come
  Due --> Running: installment paid
  Running --> Due: next month
  Running --> Finished: last installment paid
  Pending --> Pending: Change month
  state "One amount" as One
  [*] --> One: Without installments
  One --> Due: pay month has come, on that card bill
  One --> Pending: Convert to EMI (new total, count, from month)
  Finished --> [*]: shown in its last month only

Lending and borrowing with people

Every person is chosen from one list, so two lends to the same person add up. Money paid back settles the oldest lend first. Settled ones stay in the Personal tab for their month, and in the report for 12 months.

stateDiagram-v2
  direction LR
  [*] --> Lent: Lend · cash, bank or card
  [*] --> Lent: Edit an expense or card purchase into a Lend
  Lent --> Partly: Money returned (part)
  Partly --> Settled: Money returned (rest)
  Lent --> Settled: Money returned (all)
  Lent --> Settled: Gift it, not income or spending
  Partly --> Settled: Gift it (rest)
  [*] --> Borrowed: Borrow, with a pay-back month
  Borrowed --> BorrowedDue: pay month has come, counts in Due
  BorrowedDue --> Settled: Repay
  Settled --> [*]: report keeps it 12 months

What the app adds by itself

Each time a page refreshes, the app checks what is due and adds missing entries once. Anything typed by hand, or deleted on purpose, is left alone.

As SQL

-- SQLite, created by sqlite-net from DailyAccount.Core/Models/Entities.cs
-- Money: INTEGER poisha (৳1 = 100). Dates: INTEGER ticks. Months: TEXT 'yyyy-MM'. bool: INTEGER 0/1.

CREATE TABLE Account (
  Id             INTEGER PRIMARY KEY AUTOINCREMENT,
  Name           VARCHAR NOT NULL,
  NameBn         VARCHAR,
  Type           INTEGER NOT NULL,          -- 0 Bank · 1 Cash · 2 MobileWallet
  OpeningBalance BIGINT  NOT NULL,          -- balance on the 1st of the start month
  IsActive       INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE Category (
  Id        INTEGER PRIMARY KEY AUTOINCREMENT,
  Name      VARCHAR NOT NULL,               -- unique per kind across levels (EN or BN, any case)
  NameBn    VARCHAR,
  Kind      INTEGER NOT NULL,               -- 0 Income · 1 Expense
  ParentId  INTEGER,                        -- → Category.Id (one level: Bajar → Fish)
  SortOrder INTEGER NOT NULL
);
CREATE INDEX Category_ParentId ON Category (ParentId);

CREATE TABLE Transactions (
  Id          INTEGER PRIMARY KEY AUTOINCREMENT,
  Date        BIGINT  NOT NULL,
  Amount      BIGINT  NOT NULL,             -- always positive; the direction comes from Type
  Type        INTEGER NOT NULL,             -- 0 Income · 1 Expense · 2 Transfer · 3 CardPurchase · 4 DuePayment
                                            -- 5 BorrowIn · 6 LendOut · 7 LendReturn · 8 LendGift
  AccountId   INTEGER,                      -- → Account.Id (from / into)
  ToAccountId INTEGER,                      -- → Account.Id (transfer target)
  CategoryId  INTEGER,                      -- → Category.Id
  CardId      INTEGER,                      -- → CreditCard.Id (card purchase)
  DueId       INTEGER,                      -- → Due.Id (payment of a due)
  DebtId      INTEGER,                      -- → PersonalDebt.Id (lend, borrow, return, gift, lent by card)
  LoanId      INTEGER,                      -- → Loan.Id (loan money received)
  Note        VARCHAR,
  ItemName    VARCHAR,                      -- "Rice"
  Quantity    VARCHAR                       -- "5 kg"
);
CREATE INDEX Transactions_Date      ON Transactions (Date);
CREATE INDEX Transactions_AccountId ON Transactions (AccountId);
CREATE INDEX Transactions_CardId    ON Transactions (CardId);
CREATE INDEX Transactions_DueId     ON Transactions (DueId);
CREATE INDEX Transactions_DebtId    ON Transactions (DebtId);
CREATE INDEX Transactions_LoanId    ON Transactions (LoanId);

CREATE TABLE CreditCard (
  Id               INTEGER PRIMARY KEY AUTOINCREMENT,
  Name             VARCHAR NOT NULL,
  CreditLimit      BIGINT  NOT NULL,
  StatementDay     INTEGER NOT NULL DEFAULT 1,
  DueDay           INTEGER NOT NULL DEFAULT 15,
  PayFromAccountId INTEGER                  -- → Account.Id
);

CREATE TABLE Loan (
  Id                     INTEGER PRIMARY KEY AUTOINCREMENT,
  Lender                 VARCHAR NOT NULL,
  Principal              BIGINT  NOT NULL,
  TotalPayable           BIGINT  NOT NULL,  -- principal + interest
  InstallmentCount       INTEGER NOT NULL,  -- 1 for a loan without installments
  StartMonth             VARCHAR NOT NULL,  -- first installment / pay month
  DueDay                 INTEGER NOT NULL DEFAULT 1,
  PayFromAccountId       INTEGER,           -- → Account.Id
  Note                   VARCHAR,
  CardId                 INTEGER,           -- → CreditCard.Id: EMI on this card's bill
  InstallmentsPaidBefore INTEGER NOT NULL,
  NoInstallments         INTEGER NOT NULL   -- one amount until converted to EMI
);
CREATE INDEX Loan_CardId ON Loan (CardId);

CREATE TABLE Due (                          -- every liability, one row per amount per month
  Id         INTEGER PRIMARY KEY AUTOINCREMENT,
  SourceType INTEGER NOT NULL,              -- 0 Loan · 1 Card statement · 2 Bill · 3 Personal borrowing
  SourceId   INTEGER NOT NULL,              -- → Loan / CreditCard / RecurringBill / PersonalDebt
  PeriodKey  VARCHAR NOT NULL,              -- installment no. · cycle start date · bill month
  Sequence   INTEGER NOT NULL,
  Title      VARCHAR NOT NULL,
  DueMonth   VARCHAR NOT NULL,              -- '' = no month yet
  DueDate    BIGINT,
  Amount     BIGINT  NOT NULL,
  PaidAmount BIGINT  NOT NULL,
  Status     INTEGER NOT NULL               -- 0 Pending · 1 Partial · 2 Paid
);
CREATE UNIQUE INDEX IX_Due_Source ON Due (SourceType, SourceId, PeriodKey);
CREATE INDEX Due_DueMonth ON Due (DueMonth);

CREATE TABLE Person (
  Id   INTEGER PRIMARY KEY AUTOINCREMENT,
  Name VARCHAR NOT NULL                     -- unique in any letter case
);

CREATE TABLE PersonalDebt (
  Id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  PersonId           INTEGER,               -- → Person.Id
  PersonName         VARCHAR NOT NULL,      -- the person's name, for display
  Direction          INTEGER NOT NULL,      -- 0 Borrowed · 1 Lent
  Amount             BIGINT  NOT NULL,
  Date               BIGINT  NOT NULL,
  ExpectedReturnDate BIGINT,                -- pay-back month (its last day)
  AccountId          INTEGER,               -- → Account.Id
  CardId             INTEGER,               -- → CreditCard.Id: lent through a card
  Note               VARCHAR
);
CREATE INDEX PersonalDebt_PersonId ON PersonalDebt (PersonId);

CREATE TABLE BudgetItem (
  Id            INTEGER PRIMARY KEY AUTOINCREMENT,
  Month         VARCHAR NOT NULL,
  CategoryId    INTEGER NOT NULL,           -- → Category.Id (top level)
  Estimate      BIGINT  NOT NULL,
  OnlyThisMonth INTEGER NOT NULL,           -- 0 = repeats monthly
  Skipped       INTEGER NOT NULL            -- won't pay this month (struck through)
);
CREATE UNIQUE INDEX IX_Budget_Month_Category ON BudgetItem (Month, CategoryId);

CREATE TABLE SalaryRate (
  Id        INTEGER PRIMARY KEY AUTOINCREMENT,
  FromMonth VARCHAR NOT NULL,               -- an increment is a new row from its month
  Amount    BIGINT  NOT NULL,               -- 0 = stopped
  AccountId INTEGER NOT NULL,               -- → Account.Id
  Day       INTEGER NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX SalaryRate_FromMonth ON SalaryRate (FromMonth);

CREATE TABLE CardSubscription (
  Id         INTEGER PRIMARY KEY AUTOINCREMENT,
  Name       VARCHAR NOT NULL,
  Amount     BIGINT  NOT NULL,
  CardId     INTEGER NOT NULL,              -- → CreditCard.Id
  CategoryId INTEGER,                       -- → Category.Id
  Day        INTEGER NOT NULL DEFAULT 1,
  FromMonth  VARCHAR NOT NULL,
  StopMonth  VARCHAR                        -- first month without it
);

CREATE TABLE RecurringBill (                -- kept from the first version; bills are budget items now
  Id         INTEGER PRIMARY KEY AUTOINCREMENT,
  Name       VARCHAR NOT NULL,
  NameBn     VARCHAR,
  Amount     BIGINT  NOT NULL,
  DayOfMonth INTEGER NOT NULL DEFAULT 1,
  StartMonth VARCHAR NOT NULL,
  EndMonth   VARCHAR,
  IsActive   INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE AppMeta (                      -- one-time steps and "added once" marks
  Key   VARCHAR PRIMARY KEY,                -- default-budget-v1 · category-order-v2
  Value VARCHAR                             -- salary:yyyy-MM · sub:{id}:yyyy-MM → the entry added
);
MoneyEvery amount is a whole number of poisha, so ৳1,00,000 ÷ 3 adds back up exactly; the last installment takes the remainder.
One table for every liabilityDue holds card statements, loan installments, bills and personal borrowing; IX_Due_Source stops the same one being made twice.
Added onceAppMeta remembers each automatic salary and subscription per month, so a deleted one isn't added again.
